### Capture probes

- `probe_gen.lua` — per-scenario Genesis capture. One BizHawk launch
  per scenario. Detects scene transition (OW→CAVE or OW→UW or UW→OW),
  waits N settle frames, dumps full state bundle (GDMP format with
  Phase G STAT region) + screenshot PNG.
  - SCENARIO_ID = global set by orchestrator
  - OUT_BUNDLE  = `C:\tmp\g_sweep\gen_<scenario>.bin`
  - OUT_PNG     = `C:\tmp\g_sweep\gen_<scenario>.png`
  - Scene state cell at `$FF027E` (s_scene) per `nm.exe Debug.out`
  - Auto A+B+C chord f30-f300 to advance past title
- `probe_diag.lua` — diagnostic logger (per-frame scene + key cells)

### Capture bundle schema (Phase G v2 GDMP)

```
header:  "GDMP" + version=2 u32 LE + frame u32 LE + payload_hash u32 LE
regions: tag(4) + len u32 LE + payload
  PLNA  8 KB    Plane A nametable
  PLNB  8 KB    Plane B nametable
  SAT_  640 B   Sprite attribute table
  CRAM  128 B   Color RAM
  VSRA  80 B    Vertical scroll RAM
  RAM_  256 B   68K zero-page
  STAT  32 B    Phase G state cells:
                  [0]  GameMode  ($FF8012)
                  [1]  RoomId    ($FF80EB)
                  [2]  CurLevel  ($FF8010)
                  [3]  LinkX     ($FF8070)
                  [4]  LinkY     ($FF8084)
                  [5]  LinkDir   ($FF8098)
                  [6]  LinkState ($FF80AC)
                  [7]  CavePersonState ($FF80AD)
                  [8]  CaveFlags ($FF8413)
                  [9]  CurQuest  ($FF862D)
                  [10] PersonTextSelector ($FF8415)
                  [11] FrameCounter ($FF8015)
                  [12..27] ObjType[0..15] ($FF834F..$FF835E)
                  [28..31] reserved
terminator: END_ + length=0
```

### What's deferred + why

The 56-scenario sweep requires:

1. **Per-scenario boot-and-nav joypad recipes.** Each scenario needs
   Link routed from boot OW spawn ($77, $78, $8D) to the entrance
   tile of its target OW room. NES Z1 OW is 16×8 = 128 rooms; the
   target rooms range from $00 (L9Q1) to $77 (boot). Genesis has
   MODE_TELEPORT (X button + D-pad jumps rooms across 16×8 grid;
   `RoomRom/src/main.c:2637-2651`), which makes scripted nav
   tractable: per scenario, count `dx = target.col - $77.col` and
   `dy = target.row - $77.row`, emit that many LEFT/RIGHT/UP/DOWN
   button presses, then move Link onto the entrance tile.
2. **NES-side baseline captures.** True NES PALRAM/OAM/CIRAM dumps
   for each scenario. NES has no teleport debug — needs either
   manual play-through (~30s/scenario, 56 scenarios = ~30 min) or
   scripted joypad navigation from title screen (much harder than
   Genesis because file-select + start menu flow is involved).
3. **Per-domain byte-diff differ.** Compare NES vs Gen bundles after
   normalizing NES OAM (4-byte) → Gen SAT (8-byte) format, NES
   PALRAM (2-bit) → Gen CRAM (9-bit) via the canonical NES→Gen color
   LUT, NES CIRAM tile id → Gen Plane A tile id via
   `data/chr/MANIFEST.json`.
4. **Visual diff renderer.** Reuse `tools/probes/pause_visual_diff.py`
   PIL quantize_3bit + 8×8 cell aggregation + mosaic.png pattern.
