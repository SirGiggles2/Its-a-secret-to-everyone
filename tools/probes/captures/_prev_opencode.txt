## REVIEW: probe_nes_cave_transition.lua & probe_gen_cave_transition.lua

### 1. BLOCKER: Warp tile row mismatch — Genesis hotspot reads row 10, probe writes row 9

At `probe_gen_cave_transition.lua:126-127`:
```lua
force_warp_tile(15, 9, 0x24)      -- writes $24 at (col=15, row=9)
write_link_xy(15 * 8, 9 * 8 + 0x35)  -- X=120, Y=125
```

Confirmed hotspot formula from port source (`src/game/combat/collision_dispatch.c:120`):
```
row = ((link_y + 0x0B) - HUD_PX) >> 3
```

| Platform | HUD height | Row formula |
|----------|-----------|-------------|
| **NES** | 64 px (8 rows) | `(125 + 11 - 64) >> 3 = 72 >> 3 = **9**` |
| **Genesis** | 56 px (7 rows) | `(125 + 11 - 56) >> 3 = 80 >> 3 = **10**` |

The NES and Genesis have different HUD heights (64px vs 56px). For **any** Link Y value, the Genesis hotspot row is always 1 higher than NES for the same Y. The single-cell warp at row 9 is **never read** on Genesis — the engine checks row 10. The probe silently captures 130 frames of overworld gameplay, not a cave transition.

**Fix (option a):** Band-force all rows in column 15, matching NES probe's approach (`probe_nes_cave_transition.lua:112-117`):
```lua
for row = 0, 0x15 do
    force_warp_tile(15, row, 0x24)
end
```
And update `clear_warp_tile()` to clear all rows, or invert: force the tile pre-arm, clear post-arm by full-room tile republish.

**Fix (option b):** If single-cell is preferred, write to row 10, and set Y such that y_low & 0x0F == 0x0D (the Z1 gate pass). Y=125 already satisfies y_low=0x0D. Change `force_warp_tile(15, 9, 0x24)` → `force_warp_tile(15, 10, 0x24)`. And update `clear_warp_tile()` accordingly.

**Recommend (a)** — robust against any future HUD changes.

### 4. MAJOR: GEN `force_mode_walk()` writes to undocumented state range 0x027A-0x027D

`probe_gen_cave_transition.lua:86`:
```lua
local function force_mode_walk() for i = 0x027A, 0x027D do w8(i, 0) end end
```

Port source confirmed: 0x0274 = `in_gameplay`, 0x0281 = `s_scene`. The 0x027A-0x027D gap is between known cells. What these bytes do is undocumented — they're not in the ground truth table. Writing 0 to a range without knowing its function may:
- Accidentally clear a persistent flag needed for descent
- Zero a framecounter, causing timing glitch
- Have no effect (the intended outcome, unverified)

**Fix:** Either (a) remove the call if cave entry triggers without it, or (b) determine the state semantics from `src/state/` headers and only modify the specific byte(s) that control movement state. Best: remove `force_mode_walk()` entirely — field exploration showed Path A cave gate checks `standing_tile == $24` and `y_low == 0x0D` regardless of movement flags.

### 5. MAJOR: Live domain enumeration (RULE V3.1 violation)

Both probes hardcode domain names without calling `memory.getmemorydomainlist()`:
- **NES**: `"RAM"`, `"OAM"`, `"PALRAM"`, `"VRAM"`, `"CIRAM (nametables)"`
- **GEN**: `"68K RAM"`, `"VRAM"`, `"CRAM"`

If the wrong emulator core is loaded (e.g. quickerNES instead of NesHawk for NES, or a non-genplus-gx core for GEN), domain names may differ. BizHawk may return 0/garbage for a nonexistent domain name instead of throwing — this silently poisons golden data.

**Fix:** At the top of `main()`, call `memory.getmemorydomainlist()`, iterate and assert each expected domain is present, printing diagnostics. If missing, abort immediately. Example:
```lua
local domains = memory.getmemorydomainlist()
local needed = {"68K RAM", "VRAM", "CRAM"}
for _, name in ipairs(needed) do
    if not domains[name] then
        LOG(string.format("Missing domain: %s", name))
        client.exit(); return
    end
end
```
