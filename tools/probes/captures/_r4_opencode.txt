## BUGS FOUND

### BUG 1 (MAJOR) — `gen_by_pos` dict overwrite
**File:** `cave_transition_sprite_diff.py` in `match_link()`

```python
gen_by_pos = {(c.x, c.y): c for c in gen_cells}
```

If two gen sprite cells share the exact `(x,y)` (e.g. overlapping sprites), the dict silently keeps only the last one. If the NES Link cell matches the *dropped* cell, you get a false MISSING. If it matches the *kept* cell from a different sprite with coincidentally identical pixels, you get a false OK. **Fix:**

```python
from collections import defaultdict
gen_by_pos = defaultdict(list)
for c in gen_cells:
    gen_by_pos[(c.x, c.y)].append(c)
```

Then in the match loop iterate candidates and pick best match.

### BUG 2 (MAJOR) — SAT chain walk truncated at slot 64
**File:** `cave_byte_diff.py` in `gen_sprites_with_vram()`

```python
while slot not in seen and slot < 64:
```

VDP sprite slots 0-79 are valid (80 sprites per scanline, 7-bit link = 0-127). SGDK may place sprites above slot 63. Slots 64-79 silently skipped → missing Gen sprites → false MISSING/PX-DIFF for any sprite in that range. **Fix:**

```python
while slot not in seen and slot < 128:
```

### MINOR 3 — Silent asymmetric skip
When `not nc` (NES Link off-screen), the script silently continues even if Gen has nonzero cells. Could mask a frame where Gen renders Link but NES doesn't. **Fix:** Add a warning counter:

```python
if not nc:
    if gc:
        asymmetric += 1
    continue
```

and report `asymmetric` count at the end.

### MINOR 4 — No input length validation
No guards against truncated bundles. Python raises IndexError/ValueError at first bad access — clear enough for a debug tool, but a single `len()` check at load time would give a better message.

### NIT 5 — Variable name `ny` in `detect_offset`
`ny = sorted({(c.x, c.y) ...})` contains `(x,y)` tuples, not a y-coordinate. Cosmetic.
