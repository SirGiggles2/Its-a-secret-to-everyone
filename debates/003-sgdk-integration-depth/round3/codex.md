# CODEX — Round 3

1. **Audio trigger: pick Sonnet.** Use Sonnet’s `2 of 4` formula. Opus’s “any parity-oracle song failure after one debug cycle” is too hair-trigger for a whole-driver flip; Gemini’s “new music defaults XGM2” creates two audio architectures permanently. Trigger migration only when **two** are true: `3 unfixable parity bugs in 90 days`, `driver footprint >8KB`, `audio_tick >10% CPU`, or `confirmed parity-oracle song failure`. Tools: `tools/audio_parity_oracle.py` runs on every audio change and nightly full suite; `tools/profile_audio_tick.py` runs before release and on perf-touching PRs; build-size report runs every build.

2. **Fork policy: owner-approved ADR, not contributor impulse.** Any contributor may propose “needed patch,” but fork requires a short ADR approved by project owner or explicit architecture vote. Fork-worthy means one of: security fix, upstream build break, parity blocker, correctness bug with failing repro, or measured perf win **>=15%** on a profiled hot path that SGDK will not accept. Cosmetic API taste and LLM convenience do not qualify. Downgrade path: every SGDK bump review checks whether upstream now contains the patch; if yes, remove fork delta and re-track upstream. If fork carries no still-needed patch for one release cycle, it is abandoned.

3. **Gate scope: generated/transpiled code is allowed but quarantined.** `src/zelda_translated/` should be whitelisted from adapter-boundary ownership checks because it is transpiled legacy, not hand-authored policy code. But generated output must still pass raw-danger scans unless explicitly marked generated and covered by a manifest. `src/gen/` gets the same treatment: no style ownership gate, yes raw-VDP scan unless the generator is the reviewed boundary. `src/c_shims.asm` and `src/audio_driver.asm` are low-level exceptions, allowed to touch hardware, but must be named allowlist entries, not broad directory escapes.

4. **Adapter signatures: Option C, hybrid.** Sonnet is right that NES-semantic APIs are best where parity is the spec: APU register writes, controller latch behavior, timing-sensitive state. Gemini is right that forcing NES-shaped wrappers around Genesis-native sprite/DMA work adds code without accuracy gain. So: NES-semantic for audio/input/timing parity; thin SGDK-shaped wrappers for sprite, DMA, palette, and VDP operations. This best matches the Prime Directive: preserve NES behavior where it matters, stay Genesis-native where it helps, and keep the code legible for LLM maintenance.

**FINAL stance: YELLOW.** The resolved plan is adequate in direction, but not GREEN until these criteria are written into gates, ADR policy, and directory allowlists.
