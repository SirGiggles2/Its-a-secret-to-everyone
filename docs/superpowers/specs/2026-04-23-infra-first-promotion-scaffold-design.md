# Infrastructure-First Promotion Scaffold — Design

**Date:** 2026-04-23
**Plan family:** Plan W (first of a drain campaign: W → z_05 drain → z_07 drain → …)
**Status:** design approved, pending spec review

## Summary

This plan ships zero code promotion. It builds the migration infrastructure the
`best practices.md` doc declares as highest leverage: complete symbolic RAM
naming for the dirty-edge zone, a wrapper-generation tool with an idempotent
`--check` mode, a CI drift gate that locks `src/gen/*.c` to pure passive status,
a promotion-checklist template, and per-bank forwarder manifests. After this
batch, every subsequent gen/ drain (z_05, z_07, any future promotion) runs on
rails: names already exist, forwarder boilerplate is generated, drift is
impossible to sneak past the build.

## Motivation

The project is mid-campaign. `src/gen/z_01`, `z_02`, `z_03`, `z_04`, `z_06`
are essentially pure forwarders already. `z_05` still owns ~5 fns of real room
subsystem logic (tile-buffer copy, mode-11 death sub-states). `z_07` owns
~20 fns of real logic scattered across sprite / room / player / object / enemy
families. More drains are coming.

`best practices.md` §Highest-Leverage Workflow opens with:

> Build migration infrastructure first. Invest early in tools and shared
> headers that make every later conversion cheaper. This is the biggest
> efficiency multiplier.

And §4:

> Expand symbolic RAM naming aggressively. This is critical path. Without
> names, every future move is slower and riskier.

Every drain performed before the infra lands spreads raw magic offsets and
pays for forwarder boilerplate it did not need to pay for. Shipping the
scaffold first, as its own verifiable batch, amortizes across all future drains
and installs architectural guard-rails (drift gate, checklist) the moment gen/
is declared passive — closing the window for accidental regression.

## Scope

### In scope

- **State-header coverage** for subsystems visible in the dirty-edge zone.
  New headers:
  - `src/object_state.h`
  - `src/sprite_state.h`
  - `src/save_state.h`
  - `src/link_state.h`
  - `src/collision_state.h`
  - `src/weapon_state.h`
  - `src/hud_state.h`
  - `src/audio_state.h` (only if audio offsets appear in gen/)
  Extensions to existing `src/room_state.h` and `src/progress_state.h`.
  Each new header includes only `nes_abi.h` — never another `*_state.h` —
  to prevent include cycles.
- **Shared ABI cells** consolidated in `src/nes_abi.h`. Any magic RAM offset
  appearing in `src/gen/*.c` logic bodies, or crossing the gen boundary via
  extern declarations, gets a named `NES_*` `#define`.
- **Wrapper-generation tool** at `tools/emit_gen_wrappers.py`:
  - Manifest-driven (`tools/gen_wrappers/z_0x_manifest.yaml`, one per bank).
  - Marker-region bounded: only text between
    `/* <<< auto-wrappers: z_0x (generated by tools/emit_gen_wrappers.py) >>> */`
    and `/* <<< end auto-wrappers >>> */` is regenerated.
  - Idempotent: running twice produces identical output.
  - `--check` mode: exits non-zero if file would change.
  - Include block auto-emitted from target runtime prefix
    (`roomxf_` → `room_transfer_runtime.h`, `roommd_` → `room_mode_runtime.h`,
    etc.). Prefix → header mapping lives in the tool as a table.
  - Bounded size: under 200 lines of Python. Standard library only.
- **Drift gate** wired into `build.bat`. After compile, before ROM pack, a
  step runs `python tools/emit_gen_wrappers.py --check`. Non-zero exit fails
  the build. This locks gen/ passive status the moment the scaffold ships.
- **Promotion-checklist template** at
  `docs/superpowers/templates/promotion-checklist.md`, derived from
  `best practices.md` §Promotion Checklist. Future batch notes link to it.
- **Per-bank forwarder manifests** for z_01 through z_07, reflecting the
  current state of each gen/ file. These serve as the ground truth input to
  the tool and as a round-trip test.

### Out of scope

- Any code promotion. No logic moves. No behavior changes.
- Renaming existing owned symbols.
- Refactoring existing runtime implementations.
- Visual-fidelity work (title screen, CHR expansion, V64 dead zone).
- State-header coverage beyond offsets currently visible in gen/ or crossing
  the gen boundary via extern.

### Deferred

- **Plan B:** drain `src/gen/z_05.c` real-logic fns into `room_transfer_runtime`,
  `room_mode_runtime`, and friends, using the infra landed here. Targets
  identified: `z05_copy_column_to_tilebuf`, `z05_copy_row_to_tilebuf`,
  `z05_mask_cur_ppu_mask_grayscale`, `z05_update_mode11_death_sub_c`,
  `z05_update_mode11_death_sub2`. Dead statics `get_room_flags` and
  `has_item_by_level` deleted.
- **Plan C:** drain `src/gen/z_07.c` across sprite / room / player / object
  / enemy / progress runtimes.
- **Plan D+:** any further promotions as they surface.

## Architecture

### Ownership of each artifact

| Artifact | Path | Owner |
|---|---|---|
| Shared ABI cells | `src/nes_abi.h` | central ABI layer |
| Per-subsystem state headers | `src/<subsystem>_state.h` | owned runtime layer |
| Wrapper-gen tool | `tools/emit_gen_wrappers.py` | tools layer |
| Forwarder manifests | `tools/gen_wrappers/z_0x_manifest.yaml` | tools layer |
| Drift gate | `build.bat` step | build infra |
| Checklist template | `docs/superpowers/templates/promotion-checklist.md` | docs |

### State-header boundary rule

Each `*_state.h` declares symbolic constants for RAM cells the corresponding
subsystem owns. Includes `nes_abi.h` only. No cross-state includes. When a
RAM cell is genuinely shared across subsystems (e.g., `NES_GAME_MODE`,
`NES_SAVE_SLOT`), it lives in `nes_abi.h` and both state headers reference it
through there.

### Manifest schema

```yaml
bank: z_05
includes:
  - room_transfer_runtime.h
  - room_mode_runtime.h
  - room_load_runtime.h
  - room_object_runtime.h
  - room_player_runtime.h
  - room_runtime.h
  - core_runtime.h
  - progress_runtime.h
symbols:
  - old: z05_copy_column_to_tilebuf
    new: roomxf_copy_column_to_tilebuf
    sig: "void ()"
  - old: z05_has_compass
    new: roomrt_has_compass
    sig: "unsigned char ()"
  # … one entry per forwarder in the bank
```

The `includes` block is fallback; the tool can also auto-derive from the
symbol prefix table. Explicit listing wins when both present, for deterministic
output.

### Tool execution contract

- `python tools/emit_gen_wrappers.py` — regenerate all marker regions across
  all banks listed in `tools/gen_wrappers/`.
- `python tools/emit_gen_wrappers.py --check` — exit 0 if every marker region
  matches manifest output, else exit non-zero and print diff.
- `python tools/emit_gen_wrappers.py --bank z_05` — regenerate one bank.

### Drift gate wiring

`build.bat` gains a step after C compile:

```bat
python tools\emit_gen_wrappers.py --check
if errorlevel 1 exit /b 1
```

Placement: before ROM pack, so a drift failure prevents producing a ROM.

## Data flow

This plan introduces no runtime data flow. Build-time flow:

1. Developer (or AI agent) edits an owned runtime module and updates its
   bank manifest if promoting a new fn.
2. Running `emit_gen_wrappers.py` regenerates the forwarder region of the
   affected `src/gen/z_0x.c`.
3. Build compiles. Drift gate verifies `--check` still passes.
4. Parity + perf probes verify behavior unchanged.

## Error handling

- **Tool receives unknown signature grammar** → exit non-zero with line and
  bank reported. Human fixes the manifest.
- **Tool encounters missing marker region in a bank file** → treat as fresh
  insert at end of file, report via warning. Build gate does not fail (valid
  first-time state). Subsequent runs verify marker region is now present.
- **Two manifest entries share `old` symbol** → exit non-zero with duplicate
  reported.
- **Manifest references a `new` symbol whose header is not in the prefix
  table and not in `includes`** → exit non-zero asking for explicit include.

## Testing

Smoke tests in the plan, not automated suites:

1. Fresh clone of current repo state: run tool with empty manifests, confirm
   it handles empty case without writing anything.
2. Populate manifests reflecting current gen/ forwarders (authoring step in
   the plan). Run tool. Confirm zero diff against current hand-written
   forwarders. This is the critical correctness proof.
3. Run tool twice. Diff run 2 vs run 1. Must be zero bytes.
4. `--check` returns 0 on clean tree, non-zero after a deliberate manual
   edit inside a marker region.
5. `build.bat` smoke: builds identical ROM byte-for-byte to baseline.
6. `tools/compare_t34_movement_parity.py` → `T34_PARITY: ALL PASS`.
7. `python tools/compare_perf.py` → `PERF_REPORT: … 0 FAIL`.

## Risks and rollback

| Risk | Mitigation |
|---|---|
| Header include cycle | Rule: `*_state.h` includes only `nes_abi.h`. No cross-state includes. |
| Macro name collision in `nes_abi.h` | Plan step greps existing defines before adding. Reuse on hit. |
| Drift-gate false positive on hand-written pieces outside markers | Gate inspects only text between markers. Everything else is hand-owned. |
| Python missing from build env | Already required by existing `tools/*.py`. No new dependency. |
| Manifest drifts from real gen/ state after a later drain | `--check` catches on every build. |
| Tool misparses a rare signature shape | Signature grammar is documented and bounded (return type + arg list). Unknown shape → explicit failure, not silent wrong output. |

**Rollback:** revert commits. Since no code moves, behavior is identical.
Safest possible batch.

## Success criteria

- `build.bat` green end-to-end, including drift gate step.
- `tools/emit_gen_wrappers.py --check` exits 0 against committed state.
- Running the tool a second time produces zero diff.
- `T34_PARITY: ALL PASS` unchanged from baseline.
- `compare_perf.py` returns `0 FAIL`.
- ROM byte-compares identical to baseline (no code moved).
- Every `src/gen/*.c` forwarder currently present is represented in its
  bank manifest.
- `docs/superpowers/templates/promotion-checklist.md` exists and is linked
  from this spec.

## Decision log

- Considered combining this scaffold with the z_05 drain in one plan. Rejected
  to keep batch shape small, per `best practices.md` §Refactoring Safely
  ("Are refactors small? Are you doing one refactor at a time?").
- Considered doing z_05 drain first and building infra afterward. Rejected
  because the doc's own §Highest-Leverage Workflow ranks infra first as
  "biggest efficiency multiplier" and names magic-offset spread as critical
  path risk. Every drain before infra multiplies cleanup cost later.
- Considered skipping the wrapper-gen tool in favor of a CI drift grep.
  Rejected: the tool and the gate share logic; building both together costs
  little more than the gate alone, and having a canonical regenerator makes
  forwarder authorship cheap for future drains.
