# Title.md vs RoomRom — parity gap audit

**Source:** Codex CLI audit, 2026-05-04 (debate roomrom-default-rule
follow-up). Triggered by user mandate "anything done to Title.md should
also be done to RoomRom" + post-Phase-3/4 closure question of how many
phases had RoomRom-runtime evidence.

**Methodology:** Codex audited build scripts, subsystem dispatch link
lists, data file SHA gates, and closed-phase evidence under
`tools/audit/drain_findings/`. Inventory below is verbatim from Codex
with light formatting.

---

## LIST 1 — Subsystem dispatch divergence

Every drained subsystem is RoomRom-ahead. Title.md still links transpiled
`src/oracle/*_runtime.c`; RoomRom links native `src/game/*_dispatch.c`.

| Subsystem | Title.md links | RoomRom links | Severity |
|---|---|---|---|
| cave | `src\oracle\cave\cave_runtime.c`, `uw_person_runtime.c` | `src\game\cave\cave_dispatch.c`, `uw_person_dispatch.c` | RoomRom-ahead |
| combat | `src\oracle\combat\combat_runtime.c`, `collision_runtime.c`, `link_collision_runtime.c`, `targeting_runtime.c` | `src\game\combat\combat_dispatch.c`, `collision_dispatch.c`, `link_collision_dispatch.c`, `targeting_dispatch.c` | RoomRom-ahead |
| enemies | `src\oracle\enemies\enemy_*_runtime.c`, plus `src\game\enemies\c_wanderer.c` | `src\game\enemies\enemy_dispatch.c` | RoomRom-ahead |
| hud | `src\oracle\hud\hud_runtime.c` | `src\game\hud\hud_dispatch.c` | RoomRom-ahead |
| items | `src\oracle\items\item_runtime.c`, `weapon_runtime.c` | `src\game\items\item_dispatch.c`, `weapon_dispatch.c` | RoomRom-ahead |
| room | `src\oracle\room\room_runtime.c`, `room_load_runtime.c`, `room_mode_runtime.c`, `room_transfer_runtime.c`, `room_player_runtime.c`, `room_object_runtime.c`, `ow_room_render.c`, `ow_room_debug.c` | `src\game\room\room_dispatch.c` | RoomRom-ahead |

**Implication for Phase 12 promotion:** Title.md still on oracle-runtime
code. Promoting RoomRom dispatchers into Title means swapping the link
list. No regression risk for RoomRom; risk is that Title.md regression
suite drifts from new dispatcher semantics.

alone, it only compiles checked-in generated state — no NES/hash proof.
