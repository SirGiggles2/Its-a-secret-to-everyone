# Hard rules — SGDK-1..5, WT-1..4, D1

Source: `docs/superpowers/plans/2026-05-02-title-roomrom-full-port-master-plan.md` Execution Rules section.

## SGDK-1 — Adapter boundary
Code under `src/game/` and `src/frontend/` MUST NOT `#include <genesis.h>` (or any SGDK public header) and MUST NOT write Genesis hardware registers directly. All Genesis hardware access routes through `src/sgdk_adapter/`. Per-directory whitelist in `tools/check_adapter_boundary.py` and `tools/check_raw_vdp.py`. Build hard-fails on violation.

## SGDK-2 — Version pin
SGDK submodule SHA pinned in `tools/sgdk_pin.json`. Reasoning in `docs/sgdk_audit.md`. `build.bat` hard-fails on drift. Bumps require:
- `--accept-sgdk-bump` flag
- updated `docs/sgdk_audit.md`
- regenerated parity oracle baselines
- regenerated `Debug.md` checksum
All in one commit.

## SGDK-3 — Hand-rolled VDP
Default = SGDK API. Raw VDP register writes outside boot/shim/adapter require:
- profiled hot path
- ≥15% measured cycle/frame OR bandwidth improvement
- inline citation of replaced SGDK call
- entry in `docs/handrolled_vdp.md`
- adapter unit-test coverage

## SGDK-4 — Audio migration trigger
Custom driver = default. XGM2 migration of any audio subsystem (or whole-driver flip) requires ADR approval, triggered by ANY 2 of the following firing within a rolling 90-day window:
- (a) `audio_tick` >10% frame budget
- (b) parity-oracle song failure surviving 1 debug cycle
- (c) driver footprint >8KB
- (d) ≥3 unfixable `audio-parity` issues open >30d

Documented in `docs/audio_migration_trigger.md`.

## SGDK-5 — Fork policy
Project owner = sole decision-maker. Qualifying conditions:
- security CVE (no upstream patch 14d)
- parity blocker (upstream rejected/stalled 30d)
- reproducibility break (upstream refuses fix)
- build-breaker (no upstream response 14d)

Patch must be <200 LOC and touch no SGDK public ABI. Performance alone is not fork-worthy — hand-roll behind the adapter under SGDK-3 instead. Fork lives at `vendor/sgdk-fork/` with `PATCHES/`; every release attempts clean rebase against upstream and auto-PRs un-fork on success.

## WT-1 — Substrate single-writer
Shared substrate is edited from `main` worktree only:
- `src/sgdk_adapter/`
- `src/abi/`
- `src/state/`
- `data/`
- `src/audio_driver.asm`

RoomRom worktrees rebase on `main` to consume substrate changes. Single-writer invariant prevents semantically-valid divergent edits at runtime. Defense-in-depth: `tools/gates/check_banned_filename.py` runs on every commit and refuses any reintroduction of the retired aliases (`whatif.*`, `Title.*`, `RoomRom.md`, `CombinedDebug.*`) so substrate refactors cannot smuggle a second build target back in.

## WT-2 — Active scope pointer
Before any edit, consult `docs/audit/active_scope.md` (or `.active_scope`) for the current phase's allowed paths. Auto-generated by `tools/audit/active_scope.py` on phase-close commit. Edits outside the active scope trigger pre-commit warnings — advisory, not blocking.

## WT-3 — Frontend boundary
Code under `src/game/` and `RoomRom/src/` MUST NOT include headers under `src/frontend/`. Phase 12 promotion gate hard-fail enforced by `tools/gates/check_frontend_boundary.py`. Shared types belong in `src/state/` or `src/abi/`, never in frontend.

## WT-4 — Banned legacy build alias
Builds emit `Debug.md` exclusively (Sole Build Target Amendment 2026-05-08). The Phase-0 legacy alias `whatif.*` and the dual-target era aliases `Title.md` / `RoomRom.md` / `CombinedDebug.*` are permanently retired (user hard rule, debate 004 2026-05-02; sole-target pivot 2026-05-08). No build target, output filename, staging copy, variable, identifier, comment, or active documentation reference may reintroduce any of them. Enforced by `tools/gates/check_banned_filename.py` (CI fail on any banned-token hit outside `debates/`, `docs/archive/`, and the historical `docs/superpowers/{specs,plans,decisions,captures}/` trees).

## D1 — Drain-first / NES-disasm-second
Drained C in `src/game/<subsystem>/*_runtime.c` is the **PRIMARY implementation evidence**. NES disassembly (`reference/aldonunez/*.asm`, `src/zelda_translated/*.asm`) is the **SECONDARY verification + final authority** — it wins ties when drain is wrong.

Every Task gets a 4-line drain-aware header:

```markdown
- **NES source**: <file>:<symbol> [, <file>:<symbol>...]
- **Drained C**: <path>:<symbol> | NONE
- **Coverage**: FULL | PARTIAL(<missing>) | STALE(<changed>) | NONE
- **Stance**: ADOPT | EXTEND | REPLACE | GREENFIELD
```

Stance semantics:
- **ADOPT** — drain logic correct + already wired or trivially wirable; task = integration only.
- **EXTEND** — drain logic correct, needs Genesis-native swap (replace `_ppu_*`/`_apu_*` shims with `vdp_*`/`xgm_*`); behavior preserved.
- **REPLACE** — drain demonstrably wrong; requires evidence pointer (RAM trace, oracle scenario id, NES asm line). "Cleaner to rewrite" is NOT evidence.
- **GREENFIELD** — legal ONLY when `Coverage: NONE` (`tools/audit/drain_coverage.py` confirms no candidate drain).

3-gate verification:
- **Gate 1** (per-function diff, every commit touching drained C): document each drained function vs NES asm semantic match in `tools/audit/drain_findings/<phase>_<task>.md` as `MATCH | DIFF(<line>:<asm> vs <line>:<c>) | UNKNOWN`.
- **Gate 2** (per-RAM-cell trace, before phase exit): snapshot named NES RAM cells after N frames; diff Genesis vs NES capture using parity oracle schema.
- **Gate 3** (per-scenario parity oracle, before milestone tag): end-to-end input scripts + checkpoint screenshot + RAM diff via `tools/parity/diff.py`.

Enforcement: `tools/audit/drain_coverage.py` scans master plan headers + drained-C corpus + NES asm corpus; emits canonical `tools/audit/drain_coverage.json` + per-subsystem views under `docs/audit/drain/`; fails CI on malformed headers and on `Stance: GREENFIELD` claims with candidate drain.
